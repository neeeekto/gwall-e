# Структура проекта

Это **мульти-модульный Go workspace** (`go.work`, Go 1.24.6). Каждый сервис/пакет — отдельный модуль с префиксом `github.com/gwall-e/...`.

| Путь | Назначение | Статус |
|------|------------|--------|
| `pkg/` | Общие библиотеки (см. [libraries.md](libraries.md)) | Готов |
| `services/inventory/` | Инвентаризация: учёт хостов/проектов/namespace'ов, регистрация и провижининг хостов и VM, синхронизация «теневых» хостов | **Эталонная реализация** (DDD/CQRS). WIP |
| `services/gateway/` | API-шлюз: единая точка входа для фронтенда/клиентов, маршрутизация к сервисам | Заглушка (`README`: «API шлюз») |
| `services/outgate/` | Контракты исходящих взаимодействий с внешними системами: профилировка, DNS, наливка (provisioning) и пр. | Заглушка |
| `services/analytics/` | Сбор аналитики/метрик по хостам и операциям | Заглушка (`README`: «Сбор аналитики») |
| `services/audit/` (модуль `auditlogs`) | Аудит: журналирование действий над хостами | Заглушка (`README`: «Аудит») |
| `agents/` | Агенты сбора информации о хостах (см. [agents.md](agents.md)) | Заглушки, пусты |
| `web/` | Фронтенд-дашборд (Nx + React, проект `dashboard`) | Отдельный workspace |

> Назначение заглушек выведено из односложных `README` и имён модулей — это направление, а не зафиксированный контракт. Уточняй по мере появления кода. Из заявленных возможностей платформы (права на хосты, операции/массовые действия, автолечение) выделенных сервисов пока нет — вероятно, появятся отдельно или внутри существующих.

## Workspace

`go.work` сейчас включает только `./pkg`, `./services/analytics`, `./services/audit`. **`services/inventory` НЕ в workspace** — это намеренно (собирать с `GOWORK=off`). При добавлении сервиса в общий build — добавь его модуль в `go.work` (`use`).

> ⚠️ `README.md`, `Makefile` и `docker-compose.yml` в корне — **устаревшие**: ссылаются на несуществующие сервисы (`host_task`, `auto_healing`, `host_manager`, `scenario`, `audit_logs`, `apps/agent`). Не доверяй им; ориентируйся на это дерево.
