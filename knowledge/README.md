# База знаний `knowledge/`

`knowledge/` — **канон** правил проекта для ИИ-агентов и команды: язык кода, стиль,
архитектура, сборка, тесты, git-конвенции. Раскладка плоская — все доки лежат прямо в
`knowledge/*.md` без подпапок. Имена файлов — kebab-case, английские; содержимое — русское
(тех-термины и примеры — английские).

Все доки **MUST** следовать единому стандарту авторинга — см. [authoring.md](authoring.md).

## Что где живёт

- `knowledge/` — **КАНОН**: стабильные правила и конвенции проекта. Источник истины.
- `.planning/` — **ПРОЦЕСС**: планы, состояние, research. Это служебное, **не** канон —
  на него не ссылаются как на правило.
- Лог решений сейчас живёт в `.planning/PROJECT.md → Key Decisions`. Отдельные ADR-доки
  (`knowledge/decisions/`) — запланировано (v2).
- Точки входа `AGENTS.md` и `CLAUDE.md` лежат в **корне репо** (не в `knowledge/`) и
  служат тонкими указателями на эту базу. Появляются в Plan 02 этой же фазы.

## Порядок чтения

1. [authoring.md](authoring.md) — как читаются и пишутся правила (сила тегов, парность запрет→«do»).
2. Точки входа `AGENTS.md` / `CLAUDE.md` (корень репо) — короткая шапка и навигация (Phase 1, Plan 02).
3. `glossary.md` — общий язык домена *(появится в Phase 2)*.
4. `structure.md`, `build.md` — где что лежит и как собирать *(Phase 2)*.
5. `style.md`, `testing.md`, `architecture.md`, `patterns.md` — как писать код *(Phase 3)*.
6. `git.md`, `boundaries.md` — процесс и границы *(Phase 2)*.

## Памятка по авторингу

Каждое нормативное правило тегируется **MUST** / **SHOULD** / **WON'T**; каждый запрет
**MUST** сопровождаться предписанной альтернативой («do»). Полный стандарт — в
[authoring.md](authoring.md).
