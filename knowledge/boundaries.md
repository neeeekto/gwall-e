# Границы: что не трогать и где живут факты

Правила «do-not» на **уровне возможностей** (не хрупких path-карт) плюс карта владения
фактами (один факт = один канон). Цель: ИИ/команда знают, где границы «не чинить лишнее»,
и не плодят копии одного факта. Конкретные пути (`inventory` и др.) — как **примеры**, не
как жёсткий список.

Все правила следуют стандарту [authoring.md](authoring.md) (MUST/SHOULD/WON'T, парность
«запрет → do»).

## Не трогать WIP-леса

- **WON'T** «чинить»/расширять/достраивать WIP-сервисы вне `go.work` (nil-deps, `TODO`,
  пустые `internal/`-каталоги, не компилирующиеся пакеты): они намеренно пересобираются
  заново, а не сломаны. Вместо «починки наугад» — **MUST** оставить леса как есть и
  работать в активных модулях workspace; если что-то не собирается, сначала свериться с
  правилами ([structure.md](structure.md), [build.md](build.md)), а не патчить.
- Пример (не жёсткий список): `services/inventory` — WIP вне `go.work`; его актуальный
  WIP-статус — канон в [structure.md](structure.md) (владение фактом WIP там). `gateway`,
  `outgate` (только `README` + `go.mod`-заглушки, кода нет) — тоже примеры лесов, которые
  **WON'T** достраивать до появления реального кода.

## Стале-файлы не авторитетны

- **WON'T** считать авторитетом корневые/сервисные `README`, `Makefile`,
  `docker-compose.yml`, помеченные устаревшими, и **WON'T** повторять их содержимое в базе
  знаний: они протухли и расходятся с реальностью. Вместо этого — **MUST** опираться на
  канон в `knowledge/` ([structure.md](structure.md) — раскладка, [build.md](build.md) —
  команды); если стале-файл противоречит канону, прав канон.

## Никаких phantom-фич

- **WON'T** документировать поведение несуществующих подсистем/фич/файлов (per
  [authoring.md](authoring.md), no-phantom): база описывает только то, что **реально есть в
  репозитории сейчас**. Вместо «как должно быть в будущем» в правилах — **MUST** держать
  будущее в `.planning/` (планы) и в разделе «запланировано» индекса
  [README.md](README.md).

## `.planning/` — процесс, не канон

- **WON'T** ссылаться на черновики/спайки/планы в `.planning/` как на правило проекта: это
  **процесс**, а не канон. Вместо этого — **MUST** держать канон в `knowledge/*.md`, а
  `.planning/` использовать только для хода работы (планы, состояние, research).
  Расширяет блок «Что где живёт» в [README.md](README.md).

## Не ре-раздувать корневой `CLAUDE.md`

- **WON'T** запускать авто-генерацию тяжёлых секций корневого `CLAUDE.md` (например через
  `generate-claude-md`) и **WON'T** ре-раздувать его дублирующим контентом: корневой
  `CLAUDE.md` — тонкий гибрид (указатель на `AGENTS.md`/`knowledge/` + GSD-блок). Вместо
  авто-раздувания — **MUST** держать факты в `knowledge/`-каноне, а в `CLAUDE.md`/`AGENTS.md`
  оставлять только тонкие указатели, потому что раздутый вход съедает контекст-бюджет и
  расходится с базой.

## Карта владения фактами

Принцип: **один факт = один канон-док**, остальные доки **ссылаются**, не копируют
(pointer-over-copy, см. [authoring.md](authoring.md)). Ссылки в таблице — только на
существующие файлы; запланированные доки — без ссылки, со статусом «запланировано».

| Факт | Канон | Статус |
|------|-------|--------|
| WIP-статус `inventory`, членство `go.work`, раскладка модулей | [structure.md](structure.md) | существует |
| Команды сборки/запуска/тестов (вкл. `GOWORK=off`) | [build.md](build.md) | существует |
| Git-конвенции: ветки, Conventional Commits, PR, когда коммитить | [git.md](git.md) | существует |
| Стандарт авторинга (MUST/SHOULD/WON'T, парность, pointer-over-copy) | [authoring.md](authoring.md) | существует |
| Язык кода/комментариев, типизированные ID, маппинг DTO→домен | [style.md](style.md) | существует |
| Конвенции тестов: Ginkgo v2 + Gomega, спек-структура, мокинг портов | [testing.md](testing.md) | существует |
| Слои/направление импортов, Execute, query-lite, UnitOfWork, outbox+relay, PullEvents, MUST NOT CQRS | [architecture.md](architecture.md) | существует |
| Пошаговые рецепты add use case / query / aggregate / repository | [patterns.md](patterns.md) | существует |

- **MUST** искать факт в его каноне по этой карте и **MUST** ссылаться на него
  относительной markdown-ссылкой. Копировать тот же факт в другой док — **WON'T**, потому
  что копии расходятся; вместо копии — ссылка на канон.
