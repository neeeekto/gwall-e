## ADR-001: Мультиагентная архитектура с разделением ролей

**Статус:** ✅ Принято  
**Дата:** 2026-06-15

### Контекст
Для разработки сложной AI-платформы требуется чёткое разделение обязанностей между
различными AI-агентами, участвующими в разработке. Без такого разделения агенты
конкурируют друг с другом, принимают противоречивые решения и теряют контекст.

### Решение
Использовать мультиагентную модель с выделенными ролями:
- **Архитектор** — принимает технические решения, создаёт ADR и спецификации
- **Разработчик** — реализует код по спецификациям
- **Ревьюер** — проверяет качество и соответствие стандартам
- **Тестировщик** — пишет интеграционные и e2e-тесты
- **Отладчик** — диагностирует и локализует ошибки
- **DevOps** — управляет инфраструктурой и деплоем

Координация через handoff-документы в `docs/handoff/`.
Единый источник истины о проекте — `CONTEXT.md`.

### Последствия
- ✅ Чёткая ответственность каждого агента
- ✅ Отсутствие конфликтов между агентами
- ✅ Воспроизводимый контекст при смене агента
- ⚠️ Накладные расходы на создание handoff-документов
- ⚠️ Требует дисциплины обновления `CONTEXT.md`

## Как добавить новый ADR

1. Определи следующий номер (текущий максимум + 1)
2. Создай файл: `docs/architecture/ADR-{NNN}-{kebab-name}.md`
3. Заполни по шаблону из [`docs/agents/ARCHITECT.md`](../agents/ARCHITECT.md)
4. Добавь строку в таблицу «Реестр решений» выше
5. Обнови раздел «Ключевые архитектурные решения» в [`CONTEXT.md`](../../CONTEXT.md)
