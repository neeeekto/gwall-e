# CONTEXT.md — Единый источник истины о проекте gwall-e

> Этот файл является **обязательным первым чтением** для любого AI-агента, получившего доступ к репозиторию.
> Обновляй этот файл при каждом значимом изменении архитектуры, стека или состояния задач.

---

## 1. О проекте

| Поле | Значение |
|------|----------|
| **Название** | gwall-e |
| **Тип** | Мультиагентная AI-система |
| **Статус** | 🟡 Инициализация / активная разработка |
| **Последнее обновление** | 2026-06-15 |

### Описание
gwall-e — платформа для оркестрации AI-агентов. Система позволяет запускать, координировать и мониторить несколько специализированных AI-агентов, каждый из которых выполняет свою роль в рамках общего пайплайна обработки задач.

---

## 2. Структура репозитория

```
gwall-e/
├── agents/          # Реализации конкретных агентов (код агентов)
├── ai/              # Интеграции с AI-провайдерами (OpenAI, Anthropic, etc.)
├── services/        # Бэкенд-сервисы (API, воркеры, шина событий)
├── web/             # Фронтенд (UI для управления агентами)
├── infra/           # Инфраструктура (Docker, k8s, CI/CD, IaC)
├── docs/            # Документация проекта
│   ├── agents/      # Промпт-шаблоны для каждой роли агента
│   ├── handoff/     # Шаблоны и примеры handoff-документов
│   └── architecture/# ADR (Architecture Decision Records)
├── AGENTS.md        # Роли агентов, правила взаимодействия
├── CONTEXT.md       # ← этот файл
└── .roo/            # Настройки RooCode для каждого режима
```

## 6. Соглашения по коду

### Именование файлов
- Конфигурационные/документационные файлы: `UPPER_CASE.md`
- Исходный код: следовать конвенциям выбранного языка
- Handoff-документы: `HANDOFF-{YYYY-MM-DD}-{краткое-описание}.md`
- ADR: `ADR-{NNN}-{краткое-описание}.md`

### Ветки Git
```
main          # стабильная версия
develop       # интеграционная ветка
feat/{name}   # новые функции
fix/{name}    # исправления багов
infra/{name}  # изменения инфраструктуры
docs/{name}   # обновления документации
```

### Коммиты (Conventional Commits)
```
feat(agents): добавить базовый класс агента
fix(ai): исправить обработку ошибок API
docs(context): обновить технологический стек
infra(docker): добавить Dockerfile для сервисов
```

## 9. Для нового агента — быстрый старт

1. **Прочитай этот файл** полностью (ты уже здесь ✅)
2. **Прочитай** [`AGENTS.md`](AGENTS.md) — определи свою роль и правила взаимодействия
3. **Прочитай** [`docs/agents/{ТВОЯ_РОЛЬ}.md`](docs/agents/) — загрузи промпт своей роли
4. **Проверь** раздел «Текущее состояние задач» выше — пойми что сейчас в работе
5. **Проверь** папку [`docs/handoff/`](docs/handoff/) — нет ли незавершённой передачи задачи для тебя
6. **Приступай** к работе, следуя правилам из `AGENTS.md`
