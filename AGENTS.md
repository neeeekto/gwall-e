# AGENTS.md — Роли агентов и правила взаимодействия

> Этот файл определяет **кто что делает** и **как агенты взаимодействуют** в проекте gwall-e.
> Читается автоматически RooCode (как AGENTS.md) и вставляется в системный промпт других AI-инструментов.

---

## Быстрый старт для любого агента

1. Прочитай [`CONTEXT.md`](CONTEXT.md) — общий контекст проекта
2. Найди свою роль в разделе «Роли» ниже
3. Загрузи детальный промпт из `docs/agents/{РОЛЬ}.md`
4. Проверь `docs/handoff/` на наличие активных передач задач
5. Работай строго в рамках своей роли; если задача вне компетенции — создай handoff

## Роли агентов

### 🏗️ Архитектор (Architect)
**Файл промпта:** [`docs/agents/ARCHITECT.md`](docs/agents/ARCHITECT.md)
**RooCode режим:** `architect`

**Зона ответственности:**
- Проектирование архитектуры системы и отдельных компонентов
- Создание и ведение ADR (Architecture Decision Records) в `docs/architecture/`
- Декомпозиция эпиков на технические задачи
- Проверка технической согласованности решений между командами
- Обновление раздела «Архитектура» в `CONTEXT.md`

**Артефакты (что создаёт):**
- `docs/architecture/ADR-{NNN}-{name}.md` — архитектурные решения
- `docs/architecture/DIAGRAMS.md` — диаграммы системы
- Технические спецификации в `docs/specs/`

**Не делает:** не пишет production-код, не делает деплой

---

### 💻 Разработчик (Developer)
**Файл промпта:** [`docs/agents/DEVELOPER.md`](docs/agents/DEVELOPER.md)
**RooCode режим:** `code`

**Зона ответственности:**
- Реализация функций согласно техническим спецификациям
- Написание unit-тестов к своему коду
- Code review на уровне реализации (не архитектуры)
- Обновление технической документации в коде (JSDoc, godoc, etc.)

**Артефакты (что создаёт):**
- Исходный код в `agents/`, `ai/`, `services/`, `web/`
- Unit-тесты рядом с кодом
- Обновления `CONTEXT.md` (секция стека при добавлении зависимостей)

**Не делает:** не принимает архитектурные решения без ADR, не деплоит

---

### 🔍 Ревьюер (Reviewer)
**Файл промпта:** [`docs/agents/REVIEWER.md`](docs/agents/REVIEWER.md)
**RooCode режим:** `ask`

**Зона ответственности:**
- Проверка кода на соответствие стандартам и best practices
- Выявление потенциальных багов, уязвимостей, performance-проблем
- Проверка согласованности с архитектурными решениями (ADR)
- Финальное одобрение перед слиянием ветки

**Артефакты (что создаёт):**
- `docs/reviews/REVIEW-{date}-{branch}.md` — отчёт по ревью
- Комментарии в коде (TODO/FIXME с обоснованием)

**Не делает:** не вносит правки напрямую без согласования с разработчиком

---

### 🧪 Тестировщик (Tester)
**Файл промпта:** [`docs/agents/TESTER.md`](docs/agents/TESTER.md)
**RooCode режим:** `jest-test-engineer`

**Зона ответственности:**
- Написание интеграционных и e2e-тестов
- Анализ покрытия тестами, составление отчётов
- Тестирование граничных случаев и сценариев ошибок
- Поддержание тестовой документации актуальной

**Артефакты (что создаёт):**
- Тестовые файлы (`*.test.*`, `*.spec.*`, `e2e/`)
- `docs/testing/COVERAGE.md` — отчёт о покрытии
- `docs/testing/TEST-PLAN.md` — план тестирования

**Не делает:** не меняет production-код без согласования с разработчиком

---

### 🪲 Отладчик (Debugger)
**Файл промпта:** не требуется — используй `debug` режим RooCode
**RooCode режим:** `debug`

**Зона ответственности:**
- Диагностика и локализация ошибок
- Анализ стек-трейсов и логов
- Добавление диагностического логирования
- Документирование найденных корневых причин

**Артефакты (что создаёт):**
- `docs/bugs/BUG-{NNN}-{name}.md` — описание бага и его причины
- Патчи с исправлениями (передаёт разработчику)

### 🚀 DevOps-инженер (DevOps)
**Файл промпта:** [`docs/agents/DEVOPS.md`](docs/agents/DEVOPS.md)
**RooCode режим:** `devops`

**Зона ответственности:**
- Управление инфраструктурой (IaC, Docker, k8s)

- Мониторинг и алертинг

**Не делает:** не изменяет бизнес-логику приложения

## Правила взаимодействия между агентами

### Передача задач (Handoff)

Когда задача переходит от одного агента к другому, создаётся handoff-документ:

```
docs/handoff/HANDOFF-{YYYY-MM-DD}-{краткое-описание}.md
```

**Обязательные поля handoff-документа:**
1. `От кого` и `Кому` (роли агентов)
2. `Контекст` — что было сделано, что нужно сделать
3. `Артефакты` — ссылки на созданные файлы
4. `Блокеры` — что мешает продолжению (если есть)
5. `Критерии завершения` — как понять, что задача выполнена

Шаблон: [`docs/handoff/TEMPLATE.md`](docs/handoff/TEMPLATE.md)

### Эскалация

```
Разработчик → Архитектор     (архитектурный вопрос)
Разработчик → Ревьюер        (готов к ревью)
Отладчик    → Разработчик    (найден баг, нужен патч)
Тестировщик → Разработчик    (тест провалился, нужно исправление)
Любой       → Архитектор     (противоречие в требованиях)
```

### Обновление CONTEXT.md

Любой агент **обязан** обновить `CONTEXT.md` если:
- Принято архитектурное решение (добавить в ADR-секцию)
- Добавлена новая зависимость (обновить стек)
- Изменился статус эпика или задачи
- Появился или снят блокер

### Конфликты

При конфликте между решениями агентов:
1. Архитектор имеет приоритет в архитектурных вопросах
2. Ревьюер имеет право заблокировать слияние кода
3. Спор разрешается созданием ADR с явным выбором одного из вариантов

## Формат коммуникации между агентами

### Запрос помощи (внутри задачи)
```markdown
**[ЗАПРОС к {РОЛЬ}]**
Контекст: {что происходит}
Нужно: {что требуется}
Файлы: {ссылки на релевантные файлы}
Дедлайн: {срочно / в рамках спринта / по возможности}
```

### Подтверждение завершения
```markdown
**[ГОТОВО: {описание задачи}]**
Агент: {роль}
Артефакты: {список созданных/изменённых файлов}
Следующий шаг: {кому передать и что делать дальше}
```

## Стандарты именования артефактов

| Тип | Шаблон | Пример |
|-----|--------|--------|
| ADR | `docs/architecture/ADR-{NNN}-{kebab-name}.md` | `ADR-001-multi-agent-architecture.md` |
| Handoff | `docs/handoff/HANDOFF-{YYYY-MM-DD}-{kebab-name}.md` | `HANDOFF-2026-06-15-initial-setup.md` |
| Ревью | `docs/reviews/REVIEW-{YYYY-MM-DD}-{branch}.md` | `REVIEW-2026-06-15-feat-agents.md` |
| Баг | `docs/bugs/BUG-{NNN}-{kebab-name}.md` | `BUG-001-connection-timeout.md` |
| Спека | `docs/specs/SPEC-{kebab-name}.md` | `SPEC-agent-orchestration.md` |
