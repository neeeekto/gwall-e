<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer commit/push → git hooks | untrusted commit content + code crosses the local hook gate (lint/format/commit-msg/test) |
| committed `lefthook.yml` → future CI | same lint/test invocations reused; divergence would split local vs CI enforcement |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-06 | Tampering | bare `npx` in commit-msg fetching a drifted commitlint from the network | mitigate | Use `npx --no-install` — the hook fails loudly if `npm install` was skipped instead of pulling an unpinned version (Pitfall 6) |
| T-4-07 | Tampering | `inventory` WIP run/"fixed" by hooks, eroding the boundary | mitigate | `inventory` excluded from pre-push by design (D-03); pre-commit inventory lint scoped to `services/inventory/**` glob, best-effort, documented intentional (boundaries.md) |
| T-4-08 | Repudiation | a hook that no-ops silently (e.g. analytics 0 packages) read as "passed" misleadingly | accept | `analytics` 0-package no-op is documented as expected in build.md; pre-push still runs the real `pkg` ginkgo suite as the live gate |
| T-4-SC | Tampering | tool/npm installs | mitigate | Tools pinned via `make tools` (04-01); commitlint legitimacy-gated + exact-pinned (04-02); `npx --no-install` here. Keep `T-4-SC` visible across the phase. |
</threat_model>
