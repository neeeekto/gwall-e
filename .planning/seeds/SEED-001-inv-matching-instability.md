# SEED-001: У хоста нет внешнего ключа, стабильного И уникального во времени — матчинг/reconciliation при sync

## When to Surface

- При нарезке/проектировании **интеграционного сервиса**, заливающего данные из внешней инвентори.
- При проектировании логики **матчинга / дедупликации / reconciliation** «это тот же хост?».
- При обработке **повторного появления** ранее удалённого/списанного хоста.
- При выборе стратегии идентичности (новый ID vs восстановление) на upsert.

## Why This Matters — корень проблемы

Ни один внешний идентификатор хоста не является одновременно **стабильным** и **уникальным во времени**:

- **`INV`** привязан к **материнке** → при её замене **меняется** (тот же физический хост получает новый INV).
- **`IPMI MAC`** тоже привязан к материнке → меняется вместе с INV.
- **`FQDN`** наоборот — **переиспользуется**: хост удалили, новый завели с тем же FQDN. Стабилен в пределах жизни одного хоста, но **НЕ уникален во времени**.

Поэтому **gwall-e в принципе не может надёжно авто-ответить «это тот же хост?»** — это свойство реальности, а не дефект модели.

## Решения, принятые в домене (E1) — интеграция обязана их соблюдать

1. **Идентичность — наша и постоянная.** Внутренний `ID` генерим мы, он не переиспользуется.
2. **Никакого авто-мерджа.** Повторное добавление хоста = **новая запись / новый ID** по умолчанию. Матч с прошлыми записями — **только советочный** (human-in-the-loop), не автоматическое слияние/восстановление.
3. **FQDN уникален только среди `active`-хостов**; удаление освобождает FQDN. Матчинг НЕ может считать FQDN уникальным во времени.
4. **Конфликты — на человека.** Возврат удалённого/списанного хоста; «тот же FQDN/INV у другого»; добавление в другой проект по ошибке — sync поднимает **конфликт**, не решает молча.
5. **История — на event-backbone / Audit** (SEED-002), не в soft-deleted записи. Восстановления in-place с мерджем изменений нет.

**Стратегия матчинга для интеграции:** составной советочный матч (`INV` + `FQDN` + сетевые MAC + локация + временное окно) → кандидаты для человека, а не автоматическое решение. Возможен ручной reconcile.
